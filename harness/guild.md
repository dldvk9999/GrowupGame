# 길드(클랜) 시스템 (migration 154, 신규 콘텐츠, 사용자 요청 — "신규 컨텐츠 조사해서 추가")

관련 파일: `lib/guild.js`, `components/GuildPanel.jsx`(Friends.jsx 안에 모드 전환으로 통합), migration 154

## 조사 배경

방치형 RPG 업계 트렌드 웹 검색 결과("길드 시스템, 대규모 레이드"가 표준적인 사회적 콘텐츠로 자주 언급됨, "하이브리드 방치형" 트렌드) — 이 게임은 1:1 친구/로비채팅/전투력 랭킹은 있었지만 **여러 명이 함께 소속되는 그룹(길드)이 없었음**. 채팅/레이드까지는 범위가 너무 커서 이번엔 핵심(생성/가입/탈퇴/랭킹/공지)만 우선 구현.

## 기능

- **길드 생성**(`create_guild`): 이름 2~12자(중복 불가) + 태그 2~4자(닉네임 옆에 붙는 짧은 표기). 생성자가 자동으로 길드장이 됨
- **가입/탈퇴**(`join_guild`/`leave_guild`): 유저는 **동시에 하나의 길드에만** 가입 가능(`guild_members.user_id`가 PK). 정원 30명. **길드장은 다른 길드원이 남아있는 동안 탈퇴 불가**(먼저 위임하거나 다른 길드원을 내보내야 함) — 길드장이 사라진 "주인 없는 길드"가 생기는 걸 방지. 길드장 혼자 남은 상태에서 탈퇴하면 길드 자체가 삭제됨
- **길드장 위임**(`transfer_guild_leadership`): 같은 길드원에게만 위임 가능
- **공지사항**(`set_guild_announcement`): 길드장만 수정 가능, 최대 200자
- **길드 목록 탐색**(`fetch_guild_list`): 인원 많은 순으로 최대 50개
- **길드원 목록**(`fetch_guild_members`): 닉네임+레벨(활성 몬스터 기준)
- **길드 랭킹**(`fetch_guild_leaderboard`): **길드원 레벨 합산**으로 순위 산정 — 정확한 전투력 합산(장비 보너스 등까지 반영)은 매 조회마다 멤버 수만큼 `calc_combat_power`를 호출해야 해서 비용이 크므로, 레벨 합으로 근사(간단하지만 "다 같이 성장할수록 랭킹이 오른다"는 체감은 충분히 줌)

## RLS/보안

- `guilds`/`guild_members` 둘 다 **누구나 SELECT 가능**(가입 전 길드 탐색, 길드원 목록 확인에 필요) — `authenticated`의 INSERT/UPDATE/DELETE는 전부 회수, 모든 쓰기는 security definer 함수 내부로만 이뤄짐(이 프로젝트 전반의 표준 패턴)
- 생성/가입/탈퇴/위임/공지수정 전부 `auth.uid()` 기준으로만 동작, "이미 다른 길드에 가입돼있음" 같은 상태 검증을 서버에서 재확인

## UI 통합

`Friends.jsx`를 "친구/길드" 모드 전환 화면으로 확장 — 새 헤더 버튼을 따로 안 만들고 기존 "👥 친구" 진입점을 재사용(모바일 헤더가 이미 여러 버튼으로 붐벼서, 새 진입점 추가보다 기존 화면 확장을 택함). `GuildPanel.jsx`가 실제 길드 UI를 담당.

### ⚠️ 목록/랭킹이 가입 후엔 아예 안 보이던 문제 수정 (사용자 요청)

기존엔 가입 여부로 화면 자체가 완전히 갈라져서(`if (myGuild) return <내 길드 정보>;` 조기 반환), **한 번 가입하면 다른 길드 목록/랭킹을 다시 볼 방법이 없었음**(길드를 둘러보거나 다른 길드 순위를 확인하고 싶어도 막혀있었음). `viewingMyGuild` 상태를 새로 둬서 재설계함:

- 가입한 상태에서도 "📋 길드 목록"/"🏆 길드 랭킹" 탭에 항상 접근 가능(➕ 길드 창설 탭만 가입 중엔 숨김 — 동시에 두 길드 가입은 불가능하므로)
- 목록 최상단에 **"🛡️ 내가 가입한 길드"** 카드를 별도 영역으로 분리해서 항상 표시 — 클릭하면 `viewingMyGuild`가 켜지면서 기존 "내 길드 정보"(길드원 목록/공지/레이드 바로가기 등) 화면으로 전환됨
- 목록에서 내 길드 항목은 "가입" 버튼 대신 "내 길드" 버튼(클릭 시 동일하게 상세로 이동), 다른 길드 항목은 이미 가입 중이면 "가입중"으로 비활성화 표시
- 내 길드 상세 화면엔 "← 길드 목록으로" 버튼을 새로 추가해서 언제든 목록으로 돌아올 수 있음

### 진입점 발견성 개선 (사용자 제보 — "길드 정보를 어디서 보는지 모르겠어")

- **헤더 버튼명 변경**: "👥 친구" → **"👥 친구/길드"**로 변경(`App.jsx`) — `Friends.jsx` 화면에는 이미 "👥 친구"/"🛡️ 길드" 모드 전환 탭이 있었지만, 정작 그 화면으로 들어가는 헤더 버튼 자체엔 "길드"라는 단어가 전혀 없어서 못 찾는 게 당연했음
- **마이페이지에도 길드 카드 추가**(`MyPage.jsx`): `fetchMyGuild()`(기존 RPC 재사용, 새 서버 로직 없음)로 내 길드 정보를 가져와서 캐릭터 카드 바로 아래에 `[태그] 길드명 · Lv.N` 카드로 표시, 클릭하면 길드 화면(`friends` 탭)으로 이동. 길드 미가입 시엔 카드 자체가 안 보임
- ⚠️ **[심각] 버그 수정(사용자 제보 — "길드 탭에서 길드 카드가 안 보임")**: 목록 재설계 당시 예전 설계("가입 중이면 목록 자체를 안 불러옴")의 가드(`if (myGuild === undefined || myGuild) return;`)를 지우는 걸 빠뜨렸었음 — 그래서 **가입한 유저는 길드 탭에 들어와도 `guildList`가 영원히 `null`로 남아 "불러오는 중..."에서 멈춰있었음**(재설계의 핵심 목적 자체가 무력화된 상태였음). `|| myGuild` 조건을 제거해서 가입 여부와 무관하게 항상 목록을 불러오도록 수정

## 길드 레벨/경험치 (migration 169, 신규, todo.md 후속과제 이행)

길드 자체가 성장하는 축을 추가함 — 새로운 활동 추적 인프라 없이, 이미 기록 중이던 **길드 레이드 데미지**(158)를 그대로 재사용: 데미지 50당 길드 경험치 1. 최대 **레벨 20**, 레벨당 필요 경험치는 `round(5000 * level^1.5)`(전체 20레벨 총량 약 380만).

- **버프**: 길드 레벨 1당 **길드 레이드 골드 보상 +1%**(최대 +20%, 레벨 20에서), `report_guild_raid_damage`(클리어 보상)와 `sync_guild_raid`(미클리어 주간보상) 양쪽 모두에 적용. 버프 범위를 의도적으로 "길드 레이드 보상"에만 한정 — 게임 전체 경제(골드/경험치 전반)에 영향을 주면 파급 범위가 너무 커져서, 레이드 활동으로 얻은 성장이 레이드 보상으로 돌아오는 자기완결적 순환 구조로 설계함
- `grant_guild_exp(guild_id, amount)`는 내부 전용 헬퍼 — 다른 `security definer` 함수(레이드 데미지 반영)에서만 호출되도록 `authenticated`로부터 실행권한을 명시적으로 회수함(009의 `add_gold` 패턴과 동일한 방어)
- `fetch_my_guild`(154) 재정의로 `level`/`exp`/`exp_to_next` 노출(반환 컬럼 추가라 DROP FUNCTION 포함, diff로 기존 로직 순수 보존 확인)
- UI: `GuildPanel.jsx`의 내 길드 정보 카드와 `GuildLobby.jsx`에 레벨 배지 + 경험치 진행바 표시(만렙이면 진행바 대신 "✨ 길드 최고 레벨 달성!" 문구)
