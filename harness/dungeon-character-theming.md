# 던전별 캐릭터 테마 오라 (신규, 사용자 요청 — "캐릭터를 그 던전과 어울리는 일러스트로")

관련 파일: `components/DungeonAura.jsx`, `components/MonsterSprite.jsx`(`dungeonTheme` prop 추가)

## 설계 결정: 전신 리스킨 대신 테마 배경/오라

사용자 요청은 "스테이지·경험치·골드·전직·무한의 탑 던전 모두 캐릭터를 그 던전과 어울리는 일러스트로" 바꿔달라는 것이었음. 문자 그대로 캐릭터 자체를 던전마다 다시 그리려면 **9종 몬스터(3속성×3단계) × 5던전 = 45벌의 원화**가 필요해 비현실적임(코스튬 시스템도 같은 이유로 "전신 리스킨" 대신 "배지 오버레이" 방식을 택한 전례가 있음, `MonsterSprite.jsx`의 `renderCostumeOverlay` 참고).

대신 **캐릭터 뒤에 던전 성격에 맞는 정교한 배경/오라 일러스트를 깔아서** 맥락에 맞는 모습으로 보이게 함 — 초상화 프레임이 상황에 따라 바뀌는 것과 같은 원리로, 캐릭터 정체성(어떤 몬스터인지)은 유지하면서도 "이 던전에 어울리는" 시각적 차별화를 줌.

## `DungeonAura.jsx` — 5종 테마

| theme | 던전 | 컨셉 |
|---|---|---|
| `stage` | 스테이지 | 모험/따뜻한 톤 — golden 방사형 그라디언트 + 나뭇잎/광선 6방향 |
| `exp` | 경험치 던전 | 지혜/마법 — 파란 룬 마법진(이중 원+점) |
| `gold` | 골드 던전 | 보물 — 쏟아지는 금화 7개(그라디언트 원+하이라이트) |
| `job` | 전직 던전 | 각성/에너지 — 보라~핑크 방사형 그라디언트 + 8방향 번개 |
| `tower` | 무한의 탑 | 하늘/별빛 — 파란 세로 그라디언트 + 별 7개 + 구름 |

각 테마는 `<svg viewBox="0 0 200 200">` 하나로 구성된 독립 컴포넌트 함수(`theme` prop으로 분기) — 캐릭터 크기(`size`)의 1.7배로 그려져서 캐릭터 뒤로 넉넉하게 퍼지는 배경 느낌을 줌.

## `MonsterSprite.jsx` 통합

- 신규 `dungeonTheme` prop 추가 — 값이 있으면 `<DungeonAura theme={dungeonTheme} size={size} />`를 캐릭터보다 먼저(DOM상 아래) 렌더링
- 오라는 `position: absolute; zIndex: 0`, 캐릭터 본체는 `position: relative; zIndex: 1`로 명시해서 항상 오라가 뒤에 깔리도록 z-index를 확정함(단순 DOM 순서에만 의존하면 브라우저별 stacking 규칙 차이로 어긋날 수 있어 안전하게 명시)
- `MonsterSprite`를 쓰는 3개 렌더 분기(CDN 이미지 / SVG 벡터 / 폴백 placeholder) 전부에 오라를 적용해서, 나중에 실사 이미지로 전환되더라도 오라 효과가 깨지지 않음
- 부모 wrapper의 `overflow`를 `visible`로 명시(기본값이지만 명시적으로 표기) — 오라가 캐릭터 박스보다 크기 때문

## 화면별 적용

| 화면 | dungeonTheme |
|---|---|
| `BattleScreen.jsx`(스테이지) | `"stage"`(고정) |
| `DungeonBattle.jsx`(경험치/골드/무한의탑 공유) | `dungeonEnemy.dungeonType`(`'exp'`\|`'gold'`\|`'tower'`을 그대로 전달 — 마침 기존 데이터 필드명이 테마 키와 동일해서 매핑 로직 불필요) |
| `JobDungeonBattle.jsx`(전직) | `"job"`(고정) |
| `WorldBossBattle.jsx` | 미적용(사용자가 요청한 5개 던전 목록에 월드보스는 없었음) |
| 그 외 화면(마이페이지, 몬스터도감 등) | 미적용(`dungeonTheme` prop을 안 넘기면 기존과 완전히 동일하게 동작 — 하위 호환 100%) |

## 알려진 한계

- `.arena` 컨테이너에 `overflow: hidden`이 걸려있어서, 오라가 화면 가장자리에 아주 가깝게 배치된 경우(특히 좁은 모바일 화면) 오라의 바깥쪽 일부가 살짝 잘릴 수 있음 — 배경 발광 효과 특성상 완전히 안 보여도 크게 위화감은 없다고 판단해 별도 조치는 안 함
- 캐릭터 본체(species/element별 SVG) 자체는 이번에 다시 그리지 않음 — "정교하게"라는 요청 중 배경/맥락 연출 쪽에 집중했고, 캐릭터 원화 자체의 디테일 강화는 범위 밖으로 남김(추후 과제)
